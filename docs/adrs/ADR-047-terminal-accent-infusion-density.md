# ADR-047: 终端风中度融入主应用 · 银杏绿交互强调 · 密度收紧一档（修订 ADR-045 分离原则）

**Status:** Accepted
**Date:** 2026-08-28
**Related:** ADR-045（Codex 视觉语言，本 ADR 修订其「登录风与主应用刻意分离」原则并落实其 §4 密度）

## Context

ADR-045 落地后现状：token 双主题/字体打包（Inter + JetBrains Mono）已完成，但：

1. **风格融入度**：ADR-045 明确「登录赛博朋克 ≠ 主 app 中性灰，是刻意氛围设计」。用户复核后改判：希望登录页的终端/极客风在主应用内可感知（底线 Codex 极简，理想带登录风），且**功能第一**——可读性、密度、交互不受损。
2. **密度欠账**：ADR-045 §4 紧凑密度（按钮 28/输入 30/表格行 36）标注「PR6 待实现」至今未落，当前控件偏舒展。
3. **交互强调色**：`--primary` 当前为中性黑，与「银杏」品牌识别弱关联；品牌绿仅存在于 logo 与新增的 `--brand`（净值曲线）。涨跌语义绿（`--success` 142 71% 45% 亮绿）按 ADR-045 保留为数据语义。

## Decision

1. **中度融入**（修订 ADR-045 分离原则）：
   - `--primary` 由中性黑改为**银杏绿**（浅色 `135 30% 38%` / 暗色 `135 30% 58%`）：主按钮、链接、菜单选中态、焦点环一键随 token 变绿。
   - 数据排版走 **JetBrains Mono**：表格数字列（`.col-num`）、统计卡数值、指标卡，全局 mono + tabular-nums。
   - PageTitle 增加 mono 大写 **kicker**（路由段，如 `> PORTFOLIOS`），全站页面标题带终端提示符基因。
   - EmptyState 支持可选 `hint`（mono `//` 注释风副文案）+ 空态卡极淡网格纹理——终端元素只出现在「系统说话」的位置（空态/加载/标题基因），不进入数据密集工作区。
2. **密度收紧一档**（落实 ADR-045 §4，取值放宽保中文）：按钮 32px / 输入 34px / 表格行 40px（ADR 原值 28/30/36 对中文标签过紧，实测校准）。
3. **不做**（功能第一红线）：登录页 971 行不动；无全局扫描线/辉光/跑马灯/像素字体标题；浅色主题保留全功能；不碰任何业务逻辑。
4. **图表主题跟随补齐**：BarData K线图 `watch(theme)` 缺 `chart.applyOptions` 导致暗色白底，随本 ADR 修复（属 Codex 暗色底线欠账）。

## Rationale

- **为何 primary 直接改绿而非新增 --accent**：全站样式已 `hsl(var(--token))` 驱动，改 `--primary` 一处即按钮/链接/选中全生效；新增 accent 则需逐组件接线，违背 token 单一来源。绿做交互色、亮绿做涨跌，二者色相相同但饱和度/明度分档（muted 38% vs bright 45%+），同屏并列可辨。
- **为何密度取 32/34/40 而非 ADR 原值 28/30/36**：ADR-045 自我声明的风险「中文长标签在紧凑控件需实测」成立，28px 按钮装不下 14px 中文标签 + padding；放宽一档是 Codex 观感与中文可读的折中。
- **为何终端元素只放在系统语义位**：数据密集区（表格/图表/表单）任何纹理与装饰都直接损耗功能第一；标题 kicker、空态 hint、mono 数字是「机器在说话」的语义位，风格在此反而辅助信息分层。
- **已排除全面终端化**：扫描线/辉光/跑马灯损伤可读性与性能，与功能第一冲突（用户已否决）。
- **已排除纯 Codex 克制版**：用户明确希望登录风可感知，纯中性版等于维持现状。

## Consequences

- 主按钮/链接/选中态全站变绿——涨跌绿的语义纪律（ADR-045「色彩只留给数据语义」）需在 review 中持续守护：交互绿 ≠ 数据绿，装饰禁用任何绿。
- 密度收紧为全局视觉变化，需逐页双主题回归截图。
- 后续新页面沿用 kicker/mono/密度 token，无需重复决策。
